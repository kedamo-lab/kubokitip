# Кубок ИТиП

Лендинг и панель редактирования `/admin`. Дата сезона 2026 — 10.07.2026. Брендовые SVG/PNG — прямые экспорты Figma; пути SVG сохранены. Навыки `kubok-itip-brand` и `kubok-itip-motion` подключены в `.agents/skills/`.

## Запуск и данные

`node server.mjs` — сайт на http://127.0.0.1:4173, панель на http://127.0.0.1:4173/admin. Сервер выводит IP локальной сети. `HOST` и `PORT` меняют адрес и порт; по умолчанию `0.0.0.0:4173`. Локальная запись доступна с компьютера, где запущен сервер; проверяются адрес клиента, cookie, CSRF и Origin. Другие устройства сети могут просматривать лендинг.

Рабочие данные — `.local/content.json`, 20 предыдущих версий — `.local/history.json`, файлы — `.local/uploads/`. Всё сохраняется после перезапуска. Не удаляйте `.local`: эти данные не включены в Git и архив исходников. Для полного локального резервирования копируйте каталог, остановив сервер.

Опубликованный сайт: https://kubok-itip.tooth5829.chatgpt.site. Панель — `/admin`. Сохранён закрытый доступ владельца через Sites. Сервер Vinext, данные в D1 (`DB`), файлы в R2 (`BUCKET`). Начальные настройки загружаются из `public/data/seasons.json` только при пустой базе; повторная публикация не стирает правки из панели.

Локальная и опубликованная версии имеют независимые хранилища. Настройки переносятся через экспорт/импорт JSON; файлы нужно загружать в нужной версии. Экспорт JSON включает настройки и ссылки, бинарные файлы хранятся отдельно.

## Редактор

17 категорий: сайт и сезон; оформление; шапка и меню; первый экран; о турнире; команды; сетка; расписание; результаты; медиа; победители; организаторы и партнёры; финал и подвал; сезоны и разделы; файлы; расширенные настройки; история.

Меняются тексты и пустые состояния; логотипы и изображения; цвета, шрифты WOFF/WOFF2, размеры, отступы и анимации; меню и ссылки; дата, место, статус и регламент; дисциплины, фото и составы команд; раунды, матчи, счёт и прошедшие команды; галерея, видео, подписи и обложки; победители; организаторы, контакты и партнёры. Собственный CSS и полный JSON дают доступ к остальным параметрам.

«Предпросмотр» показывает черновик на ПК и телефоне. «Сохранить сайт» (Ctrl+S) применяет изменения для всех посетителей этого сервера. Отмена/повтор работают с черновиком; он автоматически сохраняется в браузере. История загружает копию в черновик для проверки до сохранения. При конфликте вкладок сервер отклоняет перезапись: экспортируйте черновик и загрузите сохранённый сайт в «Расширенных настройках».

Пустой новый сезон сохраняет архив. Копия сезона переносит содержимое целиком: перед сохранением проверьте скопированные результаты. Каждый год имеет свои тексты, порядок и видимость блоков, команды, матчи, победителей и медиа. Бренд и меню общие.

Матч сетки ссылается на расписание через `matchId`: один счёт используется в сетке и результатах. Статус `finished` показывает результат на лендинге. Победители скрыты до объявления, если не включён показ до финала.

Файлы до 25 МБ: PNG/JPEG/WebP/AVIF/GIF/SVG, PDF, MP4/WebM, WOFF/WOFF2. Для больших видео используйте ссылку. SVG со скриптами и внешними ресурсами отклоняются. Удаление записи из раздела сохраняет файл для ссылок архивных сезонов.

## Разработка

### Vercel

Репозиторий поддерживает отдельный Vercel-деплой: `vercel.json` задаёт Framework Preset **Other**, сборку `npm run build:vercel` и каталог `vercel-dist`. Поэтому Vercel не ищет `.next/routes-manifest.json`. Root Directory — корень репозитория. Удалите старые ручные настройки `.next`/Next.js, если они остались в проекте, и выполните новый Deploy последнего коммита. Для Vercel рекомендуем Node.js 22.x или 24.x.

Для полной работы панели:

1. В Vercel → **Storage → Create → Blob** создайте хранилище с доступом **Private** и подключите к проекту для Production. Vercel добавит `BLOB_READ_WRITE_TOKEN`. Для Preview используйте отдельное хранилище, чтобы тестовые изменения не попадали в рабочий сайт.
2. В **Settings → Environment Variables** добавьте `ADMIN_PASSWORD`: собственный длинный случайный пароль от 16 символов, желательно от 24. Не добавляйте пароль или токен в Git. Задайте их отдельно для окружений, где нужна панель.
3. Выполните **Redeploy**. `/admin` предложит вход по паролю. «Выйти» закрывает сессию в браузере; смена `ADMIN_PASSWORD` аннулирует старые сессии.

Настройки и двадцать предыдущих версий сохраняются в приватном Blob, с условной записью по ETag: две вкладки не могут молча перезаписать друг друга. Фото, видео, документы и шрифты до 25 МБ загружаются напрямую в Blob; сервер проверяет файл до появления в библиотеке. Большие запросы не проходят через функцию Vercel. Файлы остаются доступными архивным сезонам, повторный деплой не сбрасывает данные.

До подключения Blob лендинг показывает начальные данные, панель предлагает завершить настройку. Vercel, Sites и локальная версия имеют независимые хранилища: существующие настройки переносите экспортом/импортом JSON, медиа загружайте отдельно. При переносе проверьте ссылки на файлы.

`node --test tests/vercel.test.mjs` проверяет серверный адаптер с изолированным имитатором Blob: вход, права, CSRF, повторное создание функции, атомарную запись, историю, восстановление, загрузки и проверку SVG. Проверка против реального Blob требует подключённого хранилища и токена. `api/vercel.js` и `lib/vercel-*.mjs` используются только в Vercel; сборка Sites остаётся `npm run build`.

Интерфейсы — `public/`, серверные маршруты — `app/`, валидация и хранилище — `lib/cms.mjs`, `lib/cloud-store.mjs`. Сборка — `npm run build`. SQL-миграции — `drizzle/`, Sites применяет их при публикации; применённые миграции не изменять.

`node --test tests/cms.test.mjs` проверяет отдельный встроенный Worker на `127.0.0.1:4180` с локальными D1/R2: запись, архив, связь матчей, конфликт версий, историю, восстановление, загрузку файлов и отклонение опасного SVG. Не запускать тестовые записи против рабочего сайта.

Брендбук: https://www.figma.com/design/eg6I7lfpbwJdk0UaosOwl9/?node-id=0-1. Происхождение файлов — `public/assets/brand-assets.json`. Оригинальные Druk Text Wide Cyr и TT Travels можно загрузить через «Оформление»; пока используются системные подмены. Реальные фотографии, составы, место, регламент и имена организаторов заполняются в панели.
